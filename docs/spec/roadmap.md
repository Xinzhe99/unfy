# Unfy 路线图、商业化、分发与风险

版本：规格基线 0.1；资料核验日期：2026-10-21。负责人：产品负责人、技术负责人、发布负责人。本文的工期、预算、售价、转化率均为**规划假设**，不是已完成测试、供应商报价或销售承诺；外部能力以所链官方资料为依据。技术契约与指标事件定义见 [technical-design.md](technical-design.md)，功能验收见 [product-spec.md](product-spec.md)，取舍见 [decisions.md](decisions.md)。

## 1. 发布边界与排期原则

1. **M3 是商业 v1**：交付 Windows 10/11 x64/arm64、macOS 13+ Universal、Linux X11 的经验证基础工作流；Wayland 仅提供可用的检测、状态与通知，不承诺通用窗口迁移或越界救援。每个 OS、架构、桌面环境均须单独列出验证范围，不以一次跨编译代表支持。
2. v1 不安装特权 helper，不包含虚拟显示器或强制单屏。提权窗口、原生 fullscreen Space、独占/受保护窗口按支持矩阵跳过并解释。M4 的 Windows 虚拟屏与企业策略分轨推进，任何一个延期不阻塞另一个。
3. “能检测远程会话”与“知道捕获哪块屏”是两个独立能力。默认主屏、用户指定屏、热键切换始终可用；没有工具版本证据时只能称“手动兼容”或“检测后提示”，不能展示“自动支持所有远程工具”。
4. 虚拟显示器提供可选目标屏，不能保证同一会话中的物理屏布局完全不变；将已有窗口移入虚拟屏仍改变这些窗口的位置。需要保持原窗口完全不动且复制到另一屏的需求不属于本产品。
5. 只在上一阶段退出条件满足后进入下一阶段；未达标应延长阶段或收窄并明确标注支持范围，不能降低恢复、安全、误触发门槛以守住日期。P0/P1 未关闭缺陷不带入正式稳定发布。

### 1.3 统一质量门禁

指标按平台、OS build、工具版本、规则版本、窗口状态分别报告。总体样本仅作摘要；支持范围预先声明，已知不支持对象可排除但必须报告覆盖率，运行中的拒绝、超时、自我纠正和失败不得静默剔除。具体事件与计数口径以技术设计为准。

| 指标 | M2→M3 门禁 / 统计口径 | 不通过时动作 |
|---|---|---|
| 迁移成功 | ≥99% 合格窗口达到目标策略且读回通过；分母为计划提交时已纳入且声明可控的全部窗口，包括运行时失败导致未提交的窗口；取消/关闭/拓扑失效另列原因 | 问题应用加入后续明确例外；不得追溯改分母掩盖失败 |
| 恢复成功 | ≥99.9% 达到“原位恢复 / 按用户改动保留 / 原屏缺失时安全替代”的声明终态；另列原位精确恢复率与救援率 | 安全终态失败阻断发布；安全替代不能冒充原位恢复 |
| 误报 | 自动动作决策中，已确认无入站远程的误触发比例 ≤0.1%，并报告对应负例判定率；另要求 ≥10,000 个无远程主机小时 ≤1 次误搬 | 同时给出原始计数、观察时长与置信区间；任一严重本地误搬立即冻结问题规则。低样本不能称达标 |
| 性能 | 参考硬件、100 个合格窗口：确认触发至整个计划100窗首轮请求全部提交 p95 <300ms，包含枚举/布局/journal；同一起点至整批可见稳定读回 p95 ≤1s | 16窗分批不改变整批计时终点；检测去抖单列；超时计失败与超预算。macOS AX 未实测达标则不宣称达标，不以 Windows 结果代替 |
| 空闲资源 | 完成首次启动/扫描后持续 30 分钟采样：总相关进程 CPU 平均 <1%（记录核数与归一口径）；RSS <120MB（包含 WebView 子进程） | 检测源事件化或降低轮询；后台设置窗口不常驻渲染；保留上界与 p95 图 |
| 稳定性 | 公测同意上报或受控实验：无崩溃会话 ≥99.9%，P0/P1 为 0；无遥测用户不计成“无崩溃” | 3 次启动失败/10 分钟触发本地保护：暂停自动动作与自动安装，保留安全恢复 |
| 更新 | 已开始且具备安装条件的更新 ≥99% 成功；恢复阻塞单列，不能强行重启；每平台 ≥50 次升级/故障回退演练 | 暂停 rollout；将安全回退版本作为较高版本的修复构建发布，不绕过反回滚检查 |

自动误触发有两种分母：用于产品体验的“错误自动动作 / 全部自动动作”，以及用于检测评价的“误判远程 / 全部已标注无远程决策”。两者同时记录且不得混用；上述 ≤0.1% 同时作为两者的退出上限。检测按独立连接episode与预排30分钟负例观察窗去重，unknown不计TN；详见技术设计§13。精确计数、活跃主机、主机小时与无崩溃会话来自受控实验或另行同意的公测研究；生产匿名遥测只有分桶趋势，不能充当这些分母。人工确认、实验观察与回放标签负责建立 ground truth。

### 3.3 License 服务与离线语义

License 服务与规则/更新服务分离；MoR 负责交易，Unfy 负责权益。下列字段是**本产品拟定协议**，不是第三方 SDK 参数：签名 entitlement 包含 `license_id`、匿名安装设备公钥指纹、`plan`、`features`、`issued_at`、`expires_at`、`paid_until` 或 `trial_until`、`entitlement_revision`、签名键标识。具体序列化与验证由技术设计冻结。

| 情形 | 规定行为 |
|---|---|
| 在线激活 | 浏览器完成购买/登录后取得短时激活凭证；客户端不得包含 MoR API 密钥。服务端确认付款事实后签发权益，不相信网页“支付成功”跳转 |
| 个人设备配额 | 最多 3 台激活主机；安装随机身份与本地密钥绑定，不上传硬件序列号。支持自助撤销旧设备与迁移；设备重装可通过账号找回。达到额度时展示设备列表，不影响现有免费功能 |
| 在线续期 | 客户端约每天尝试后台刷新，失败指数退避。签名凭证每次最长 90 天，且 `expires_at ≤ paid_until + 14 天`；不得通过重复离线重启重置有效期 |
| 离线运行 | 有效签名凭证可用至其明确到期日；“90 天”是单次签发上限，不保证任意时点断网后再有 90 天。凭证到期前提醒连接；过期仅停止发起新的付费策略，免费检测/恢复/救援继续 |
| 续费失败/取消 | 取消自动续费不立即取消已付期间；支付期结束最多 14 天宽限，且不可越过已签凭证期限。付款补齐后重新签发；不得无限离线宽限 |
| 试用 | `expires_at ≤ trial_until`；没有额外 14 天宽限。免费用户离线无须登录；首次 Pro 试用须联网签发，防滥用不采集硬件指纹 |
| 退款/撤销/设备释放 | 在线收到撤销后待当前事务安全结束再失效；离线旧凭证不能被即时撤销，最长暴露窗口为剩余 90 天。服务端防重复签发与额度滥用，接受此离线取舍，不宣称即时全网封禁 |
| 时钟回拨 | 检查最近可信服务器时间与本地单调时钟证据；可疑且无法证明凭证仍有效时，仅暂停新的付费策略并提示联网，不中断既有事务恢复、免费功能或安全更新，不惩罚性搬窗或抹除模板 |
| Enterprise 离线 | 按年度合同签发绑定租户/设备清单或受管席位的离线文件；有效期到合同结束，续约需导入新签名文件。是否提供额外宽限由合同写明；无法实时撤销是销售前披露的限制 |
| 服务停运 | 提前提供可验证的离线迁移方案/已付权益处理；免费安全功能持续可用。运营应有数据导出、签名键托管与权益恢复演练，不许把所有窗口操作绑到在线鉴权 |

支付回调必须验签、去重、处理乱序、以服务器交易状态对账；至少测试购买、续费、退款、拒付、重复/迟到事件和断网。Paddle 官方确认 webhook 为至少一次投递，可能乱序，使用事件身份去重并按事件时间处理；具体提供商 endpoint、字段和 SDK 版本在集成时锁定并测试，未确定项标 `[待验证]`。[Paddle webhook 语义](https://developer.paddle.com/webhooks/about/how-webhooks-work/)、[签名校验](https://developer.paddle.com/webhooks/about/signature-verification/)。

### 3.5 转化、支持与隐私

官网 landing 顺序：展示真实“远程前 → 单屏远程 → 断开后”的演示；说明安装在被控主机；列出平台/工具/版本的自动、提示、手动能力；展示恢复保护、免费边界与价格；提供权限说明、兼容性检查与下载。不得写“零误报”“任何软件都能自动知道捕获屏”“物理屏完全不受影响”。M4 虚拟屏不得出现在 v1 的已可用功能栏。

产品仅在用户打开高级模板/规则时提供试用入口；在至少一次成功安全恢复之后可以温和提示，不在远程中、错误恢复中或权限异常时促销。转化事件需用户选择加入匿名遥测；结账统计与桌面遥测分开，不因拒绝遥测阻断购买或更新。

| 支持层级 | 处理方式 | 运营目标（非默认合同 SLA） |
|---|---|---|
| 自助 | 支持矩阵、权限向导、恢复按钮、错误码、规则 dry-run、可复制环境摘要 | 常见问题不要求用户定位系统日志路径 |
| Free | 知识库与尽力处理的反馈队列 | 每周分流；严重恢复/安全问题与付费用户同优先级 |
| Pro | 产品内生成诊断包后用户预览并主动上传；邮件/工单 | 2 个工作日首次响应；复杂问题说明下一步实验 |
| Enterprise | 指定联系人、变更窗口、受管版本与部署 runbook；紧急级别按合同 | M4 根据实际值班能力约定，首发不承诺 24×7 |

隐私政策必须明示：不采集屏幕内容、录屏、键盘内容或远程访问凭据；不会把窗口标题、原始第三方日志、进程命令行、IP/主机名、文档路径作为默认遥测。检测必要的本地元数据仅本地处理；导出默认脱敏并有预览，原始日志只能逐项选择附加。数据目的、保留期、存储地区、删除通道、子处理商与用户同意由 M3 法务核验。详细本地日志/遥测字段与保留策略以技术设计为唯一契约，客服不得另行要求超范围采集。

### 4.2 更新事务与发布操作

顺序是：检查签名元数据与兼容性 → 后台下载 → 验包签名/版本/哈希 → 等待合适时机 → 暂停新自动动作 → **先恢复窗口并原子写入 journal 安全终态** → 安装 → 重启自检 → 才允许重新 Armed。远程活动默认延期；用户主动“现在更新”也要先安全恢复。恢复失败、目标会话已离线、另一个用户拥有未处理 journal 时不能假定成功，不强杀、不清日志；提示或交给下次登录恢复。

| 机制 | 发布契约 |
|---|---|
| 无感范围 | 可静默下载和校验；每用户安装在具备权限时静默更新。系统安装、驱动安装、权限重授权或 OS 重启需要系统/管理员流程，禁止把“无感”写成绕过 UAC/TCC |
| 通道 | internal → beta → stable；稳定分批 1% / 5% / 25% / 100%，每批至少 24 小时且达到规定样本才扩大；低样本延长观察。客户端持久化随机 rollout 分桶，不用硬件指纹 |
| Kill switch | 独立签名、限作用域、带过期时间；可停某规则/某平台自动动作或暂停更新，不能执行脚本、关闭恢复、删除快照、远程搬窗或扩权 |
| 回退 | 安装前保留最后可用版本与兼容配置/journal 备份；单调 schema 迁移必须可被恢复组件读取。安装器原子替换/失败回退能力按包型验证；Windows 被占用二进制无法保证自回退时提供已签名修复安装器与手动路径，不能把插件当成自动 A/B 回滚系统 |
| 崩溃循环 | 连续失败进入本地安全模式：不再自动迁移、不循环安装，优先处理恢复；版本撤回后分发较高版本号的已签名修复版，保持反回滚策略 |
| 可观测性 | 更新阶段、结果码、原版本/新版本、恢复阻塞原因、本地诊断；不包含窗口内容。拒绝遥测的主机在本地保留结果，不能算作在线成功样本 |
| 事故流程 | 发布值班确认 → 停止 rollout/禁用问题规则 → 保留已签包和证据 → 发布状态说明 → 修复/灰度回退 → 复盘。主动通知/邮件渠道须用户另行订阅 |

| Mac App Store | 不列入 v1；将来需单独产品能力与商业模式评估 | 私有 API 与 App Review 2.5.1 不兼容；沙箱、自更新、许可亦有额外条件。不能通过公证推导 MAS 获准。[Apple 审核规则](https://developer.apple.com/app-store/review/guidelines/) |

渠道必须有单一更新所有者标记；官网/Cask 自更新、系统包管理、MDM/Store 之间禁止同时抢写。包管理器或企业强制替换不能由应用完全阻止：部署文档要求维护前触发用户态恢复；应用保留可跨版本读取的 journal 作为外部中断后的补救。

### 4.4 CI/CD 与企业部署

| 流程 / 平台 | 必做工作 | 验收证据 |

## 6. 风险登记册

概率为规划判断：高 ≥50%、中 20%–49%、低 <20%；影响：灾难=安全/错误会话/无法恢复，严重=主路径失效或发布时间延期，一般=局部体验与可控成本。概率并非测量结果，每两周根据证据重估；一个风险必须有单一 accountable owner，可协作但不共同失责。

## 7. 商业发布签核记录要求

M3 每次候选版必须由产品、QA、技术、安全/发布四个角色确认：支持矩阵真实；所有 P0 用例有可追溯结果；误报与恢复原始计数满足门禁；签名/更新回退合格；授权/取消/退款可操作；条款、隐私、客服已上线。遗留 `[待验证]` 若涉及默认动作、安全、安装或付款，必须验证完成或从该版本的承诺范围明确移除；仅 M4 研究项允许带着验证计划保留。签核是未来工程交付的要求，本规格不宣称这些实验或审核已经完成。
