# 04 · UI / UX 实施规格

状态：待实施。基线：2026-10-25 的源码与正在运行的 Windows 应用。本文是行为契约，不代表已经修复。

## 1. 当前问题与设计边界

已目视检查概览、显示器、排除的应用、设置四页，窗口外框 912×718，浅色、中文；导航和滚动可用。当前问题主要是状态与操作不匹配、错误处理和信息层级，不需要重新设计品牌或增加装饰。

- 概览实际同时显示「就绪」「已收拢窗口 6」「还有 3 个窗口没能恢复原位」，提供整理而非恢复。根因需由引擎解决，不能只改标签条件。见 `crates/engine/src/lib.rs:545–569`、`pages/Overview.tsx:94–126`。
- 「部分待恢复」把整理失败、恢复失败、崩溃待处理合并；「仍在原处」无法解释恢复失败后窗口究竟在哪。见 `Overview.tsx:233–273`。
- 失败卡片的主要出口是「全部排除」；排除页还错误声称排除后不再恢复。见 `Overview.tsx:393–431`、`Exclusions.tsx:62–65`。
- 预览占用主要版面，却缺少稳定的逐窗结果；默认叠放时会隐藏重叠窗口的名称。见 `components/PlanPreview.tsx:31–77,159–200`。
- 目标卡片、切换下一屏、手动远程标记、整理、预览的行为不同，但用户无法预判哪些会搬窗。
- 恢复倒计时建议点「保留当前布局」取消；实际会丢弃恢复基准。见 `App.tsx:396–434,978–985`。
- 设置包含四级灵敏度、多个相互依赖的自动操作开关、无实际上传实现的统计开关、开发构建更新配置细节。见 `General.tsx:97–185,305–345,437–447`。

硬约束：保留当前中性浅/深色视觉、已有应用图标和品牌；侧栏不恢复重复的 Unfy 字标。**托盘使用现有原始图标，颜色不随就绪、整理、暂停、失败或主题状态改变。** 不新增换肤、图标颜色配置或动画。

## 2. 信息架构

保留现有四个页面文件与导航结构，不为合并页面重写路由。文案改为：

| 入口 | 回答的问题 | 内容 |
|---|---|---|
| 概览 | 现在该做什么、哪些窗口仍未完成 | 目标屏、事务状态、一个主操作、最近一次逐窗结果 |
| 显示器 | 窗口要到哪块屏、怎样收拢 | 目标选择、识别编号、默认移动方式；网格收进高级区域 |
| 排除的应用 | 哪些应用是我主动不想移动的 | 已保存规则、正在运行的应用选择器 |
| 设置 | 常驻、快捷键、自动化、更新 | 常用设置优先；诊断/历史/重置在折叠的「帮助与诊断」中 |

概览默认只出现：目标、当前状态、主/次操作、最近一次结果。预览为可展开的辅助内容，活动历史默认只展示最近一次并可展开；救援只在存在越界窗口或「更多」中提供；诊断与配置目录从概览移至设置。保留实际需要的工具，不平铺成仪表盘。

## 3. 状态与操作

以下 UI 状态由后端统一返回 `allowed_actions` 与事务摘要派生，前端不得再凭 `state === "active"` 判断是否存在恢复记录。托盘、热键使用同一动作判定。

| 状态 | 标题/正文 | 主操作 | 次操作 |
|---|---|---|---|
| 首次未确认目标 | 选择远程画面中能看到的屏幕 | 选择显示器 | 显示编号 |
| 就绪且有异屏窗口 | 可将 N 个窗口移到显示器 X | 整理到显示器 X | 预览 |
| 所有合格窗口已在目标屏 | 窗口已在显示器 X | 无需整理（非可点击） | 更换目标 |
| 单屏但有越界窗口 | 有 N 个窗口不在可见区域 | 找回越界窗口 | 查看详情 |
| 正在整理/恢复 | 正在整理/恢复 N/M 个窗口 | 进度；禁用重复写操作 | 可浏览其他页 |
| 已整理 | 已移入 N 个；有可恢复记录 | 恢复整理前布局 | 收拢新窗口；更多 |
| 部分整理成功 | 已移入 N 个，M 个未完成 | 恢复整理前布局 | 查看未完成；仅重试这些窗口 |
| 等待自动恢复 | 远程连接已结束，N 秒后恢复 | 立即恢复 | 取消本次自动恢复 |
| 部分恢复成功 | N 个已恢复，M 个仍需处理 | 重试恢复 | 查看详情；更多 |
| 崩溃恢复待处理 | 上次运行留下可恢复记录 | 查看并恢复 | 稍后处理 |
| 目标丢失 | 已选显示器不在当前桌面 | 重新选择显示器 | 恢复已移动窗口（若有） |
| 权限不足/存储故障 | 明确缺哪项能力及影响 | 授权/重试检查 | 查看恢复记录；诊断 |

自动化暂停是独立的小标签「自动整理已暂停」，不能盖过部分恢复失败或正在执行的状态。暂停只禁止新的自动动作，用户仍可手动整理、重试和恢复。手动点击恢复立即开始，断连延迟仅影响自动恢复。

恢复记录仍在时：任何页面、隐藏再显示、预览、刷新失败、暂停都必须保留恢复入口。已有记录数量与已成功移动数量必须分开；不把 `preimages.len()` 标成「已收拢」。

## 4. 操作细节

### 4.1 收拢与预览

默认模式显示「移到目标屏」，说明为「保留窗口大小和最大化状态，把其他屏的窗口移过来。目标屏已有窗口保持原样。」不再使用含糊的「默认」作为唯一解释。

主操作无需先点预览。预览调用只读；展示目标、将移动/已在目标屏/主动排除/系统限制/无法处理的数量。叠放是默认移动的正常结果，不画出虚假的网格。图示下面始终有可读的应用列表；名称不会因为矩形重叠而消失。不同窗口用应用名+序号区分，默认不采集/存储文档标题。

预览属于「计划」，操作结束显示「实际结果」。不得让两者同名，或把执行后的重新计算预览冒充执行回执。目标、布局配置或拓扑变化后标记预览已过期；执行端负责复核，不以旧图静默执行。

### 4.2 目标选择

首次选择仅保存目标；无窗口被移动。当前已有整理事务时，点击另一张卡片后呈现内联确认：「将已整理的窗口移到显示器 X，并保留最初的恢复位置」；按钮「移到这块屏」「取消」。零平台变更的失败保留旧目标；部分成功显示新目标与未完成项，不用旧目标标识掩盖已经发生的移动。完整成功才显示「使用中」，首次基准和恢复入口始终保留。

移除与卡片重复且行为不一致的「切换到下一块屏」按钮；托盘保留「目标显示器」子菜单及编号。不得在显示器丢失时静默回退主屏并继续整理。编号明确为「Unfy 编号」，除非后端确实与系统编号一致，不暗示等同 Windows 设置中的编号。

截图是可选识别辅助：进入页面抓取一次、拓扑改变刷新、提供「刷新画面」。不每两秒全屏编码；隐藏窗口停止抓取；排除页不抓屏。截图失败显示「暂时无法获取预览，仍可按编号选择」，不把黑色像素解释为显示器断开。截图不写日志、诊断或遥测。

### 4.3 失败结果

结果持续显示直到下一次操作或用户收起，不能只保留六秒提示。每个未完成窗口具有应用、来源屏、结果、原因、可执行的下一步。

| 原因 | 文案示例 | 下一步 |
|---|---|---|
| 权限不足 | 此窗口以更高权限运行，当前无法移动 | 保留原位；说明手动移动；不诱导整体提权 |
| 大于目标工作区 | 此窗口最小尺寸超出目标屏，已移入并保留可操作区域 | 标为「已移入，部分超出」；不是失败或精确排列 |
| 应用调整位置 | 已发送移动请求，但窗口回到了原处 | 单窗重试；查看结果 |
| 窗口已关闭 | 操作前窗口已关闭 | 安全终态，无需重试 |
| 整理期间用户调整 | 你之后调整过此窗口，已保留改动 | 说明它没有恢复到原位置 |
| 原屏缺失 | 原显示器已断开，窗口留在当前可见屏幕 | 等屏幕恢复后再试；保留原恢复记录 |
| 原生全屏/其他桌面 | 当前平台不能安全移动此窗口 | 说明退出全屏/切回该桌面后再整理 |
| 身份无法确认 | 无法确认是否仍是原窗口，尚未移动 | 查看详情；不把旧位置套给同名新窗口 |

「不再整理此应用」是用户主动的二级菜单选项，不作为失败卡片的默认解决办法；移除「全部排除」。排除只影响之后的收拢，已存在的恢复责任仍保留。排除页文案改为「以后整理时跳过这些应用；已经整理的窗口仍可恢复。」

### 4.4 取消、保留与退出

- 「取消本次自动恢复」仅取消计时器；不删除事务或快照。
- 「保留当前位置并结束本次整理」放入「更多」。点击后确认框准确说明：「这次整理的恢复位置将被放弃，之后不能用本次记录恢复。」显示受影响数量，默认焦点为取消；后端完成持久化后关闭事务。
- 关闭主窗口继续驻留托盘；首次说明一次，不每次弹窗。
- 退出时存在记录：提供「恢复后退出」「暂不退出」；确实要放弃记录走上述明确确认。恢复失败停留在结果页，不退出、不建议关闭用户工作窗口。
- 「稍后处理」仅收起提醒，恢复记录和托盘入口持续存在。

## 5. 设置与引导的收缩

常用设置顺序：开机自启 → 快捷键 → 自动化 → 外观 → 更新 → 帮助与诊断。

删除/合并：

- 删除没有实际上传功能的「使用统计」开关与字段；不新增遥测系统。
- 删除「标记为远程会话」独立动作；手动「整理/恢复」就是用户显式的开始/结束入口，不再需要先改变检测器状态。
- 四级「灵敏度」替换为「手动」和仅对通过连接证据验收的来源开放的「可靠连接触发」。进程存在只显示信息，不能启用自动移动。具体证据见 03。
- 不单列「远程端能看到全部屏幕」开关；用户不需要收拢时选择手动即可。迁移旧值必须保持“不自动移动”的原意。
- 排列只保留默认移入和已有网格；移除主次布局及其独立参数。现有 `primary_side` 设置的迁移规则见 05，不能静默重排当前事务。
- 边距/间距仅在网格高级区域出现；默认移入不显示不起作用的参数。
- 无更新源的开发构建显示「开发版本，自动更新不可用」，相关开关禁用；不向普通用户展示签名公钥等实现术语。
- 引导压缩为两步：说明安装在被控主机、确认目标与必要权限；然后给「整理一次」与可选快捷键。自动化后置，未证实工具不出现「自动（推荐）」。去掉「这不是失败」和免费/账号的无关说明。

## 6. 前端数据与可访问性

修改 `App.tsx`、`api.ts`、页面 props，复用现有组件；不引入全局状态库或第二套设计系统。

1. `get_status` 返回单次一致快照：操作 id、事务摘要、自动化状态、目标状态、允许动作、最新结果引用、递增 revision。所有页面和托盘使用同一语义。
2. 核心状态加载与更新检查/诊断独立失败；当前 `Promise.all` 中一个非核心请求失败不能让整个首页永久停在载入。
3. 状态轮询只作兜底，页面可见时每 4 秒；同类请求 single-flight，旧 revision 不覆盖新结果。显示器图像和应用列表有独立的可见性生命周期。
4. 事件含 operation_id/revision；结束、取消、重连时清理对应计时器。普通设置保存不得让主按钮显示「正在恢复」。
5. 无障碍：所有数字输入有明确 `label/id` 关联；分段选择有选中状态与方向键；提示和错误通过 status/alert 宣告，不用颜色独自表达。新失败结果出现不抢键盘焦点。
6. 尺寸：内容文字以 13–14 CSS px 为基线、说明至少 12px、常用按钮至少 32px 高；不靠缩小字体塞内容。沿用配置的默认客户区 896×679、最低 720×520 逻辑单位；本次 100% Windows 外框观测为 912×718，不把外框像素当客户区设置。125%/150% DPI 下主操作、状态、目标及恢复入口无需横滚；长应用名允许截断且可展开完整名称。
7. 中文/英文、浅/深色、键盘完整操作必须真机检查。已有色彩 token 保留；不增加品牌色。

## 7. 托盘契约

改 `apps/desktop/src-tauri/src/tray.rs`：安装时使用现有 `default_window_icon()`；删除 `state_icon` 的运行时像素重染色及 `refresh` 内的 `set_icon`。图标不根据状态或主题更换、不增加变色开关。状态用 tooltip 文本和菜单勾选/禁用表达。

菜单顺序：状态（不可点）→ 整理/收拢新窗口 → 恢复整理前布局 → 目标显示器 → 自动整理暂停/继续（仅启用自动化时）→ 打开 Unfy → 退出。救援在检测到越界窗口时提供；不出现独立远程标记。图标单击打开/激活窗口，不在用户无意点击时把已打开窗口隐藏。

验收：idle/working/active/paused/recovery/error、浅深色及多次刷新后托盘源图像 RGBA 完全相同；实际系统托盘中肉眼核对原图标。系统渲染本身的差异不冒充应用换色。恢复入口受事务约束，不受错误的 Idle 标签影响。

## 8. 完成判定

UX-01 有未完成事务时进入预览、切页、隐藏再显示，恢复按钮持续存在。

UX-02 当前一屏但有越界窗口时能救援；全在目标屏时解释无需移动；不以屏幕数推断窗口状态。

UX-03 取消倒计时后仍能手动恢复；保留布局必须明确确认放弃记录。

UX-04 任一失败可在结果列表中找到对应应用与原因；排除不是默认修复；重启后待处理仍能解释。

UX-05 更改目标卡片与托盘选择遵循同一事务行为；未选中/丢失时不能静默移动到另一块屏。

UX-06 所有设置要么产生真实效果，要么明确禁用；统计假开关、远程标记和重复循环按钮消失。

UX-07 托盘各状态保持原色；退出/关闭/恢复通过真实 UI 分别验收。

UX-08 可见性、慢 IPC、单个更新请求失败、快速连续切页不造成假忙碌或状态回退。数字输入外部更新后显示持久化后的值（不要继续用不会同步的 `defaultValue`）。
