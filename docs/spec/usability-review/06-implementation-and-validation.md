## 2. 关键兼容切换

- 改公共 Rust 类型前查全部引用与实现；Windows、mac、Fake、测试构造和 IPC DTO 一起迁移。Fake 扩展为可表达延迟应用、模式拒绝、身份复用和权限变化的可控测试后端，不承担生产降级。
- `KeepLayout` 从虚拟桌面缩放改为逐窗移入：settings、纯布局、预览、执行、再次整理、tray/hotkey、reset 和文案同一次切换。保留单一默认，不留旧算法别名或按入口分叉。
- 主次布局、marker、telemetry、弱信号级别等只在设置迁移解析器中识别旧值；产品运行路径、命令注册、前端 API、托盘、i18n 和死测试同步删除。旧值可读不等于继续保留旧功能。
- 已在磁盘的 schema/设置必须可解释；未知身份降为待确认，未解决日志不删除。修目录迁移和恢复扫描前不做批量数据清理。
- 字段名可以遵循仓库习惯，行为不能缩水：`Applied` 与 `Resolved` 分离、原位不变、状态读取无副作用、自动动作必须有真实授权证据。

## 3. 需要保留的行为回归

在现有文件扩展，不另建平行测试框架。只为可导致用户可见错误的边界、状态转换、失败和恢复保留测试。

| 现有位置 | 必须覆盖的新增/修正行为 |
|---|---|
| `crates/engine/tests/behaviour.rs` | Active/Error 预览不变；准备失败零写；mode-only 外部变化；原屏丢失后 retarget 基准；实际读回决定结果；部分完成后重启 |
| `crates/engine/tests/exit_barrier.rs` | 强制构造确实 unresolved/日志不可读/Closed flush 失败；证明退出和更新阻断，不用 `if pending` 条件绕过断言 |
| `crates/engine/tests/pause_and_delay.rs` | 暂停与事务独立；取消 deadline 不丢记录；重连发生在锁等待期间仍撤销；同连接重复结束不重排计时 |
| `crates/journal/tests/recovery.rs` | 每个写入/flush 边界失败；坏头/未知 schema/混合 tx/Closed 后数据；多个文件；重复 intent；解决记录跨重启不重开 |
| `crates/layout/src/lib.rs` 现有测试模块 | 目标已有零移动；空屏不影响尺寸；单比例缩小与 minimum 冲突；MoveOnly；负坐标/DPI；全 unplaced 结果完整 |
| `crates/settings` 现有测试 | 合法旧 schema 迁移、失败保持有效设置、reset/runtime/startup 同义；递归数据迁移中断与双目录 |
| `crates/detect` 与 `schedule` 现有测试 | 查询失败不是断开；候选不得授权；多个连接；暂停/重连/维护代次优先；用可控时钟，不在单测等真实 15 秒 |
| 前端现有交互测试 | 有恢复责任时入口可见；取消和 Keep 调用不同动作；结构化错误可读；异步旧 revision 不覆盖新结果；非核心失败不阻断状态 |

删除把源码片段、按钮文案、CSS 拼写、固定测试数量或内部结构当成正确性的测试，不因 UI 精简而重新钉住新文案。保留真实可访问性行为（标签关联、键盘、焦点、语义状态）与用户可见状态转换。托盘原图颜色通过实际资源/渲染证据验证，不靠断言源码必须包含某个函数名。

既有测试若把“删除旧未完成 journal”“换目标覆盖原基准”当正确结果，按新契约替换。不能缩小断言范围后把仍未恢复窗口计成 PASS。

## 4. 实际运行验证

### 4.1 先修测试隔离

现有 `crates/platform/win/src/bin/e2e.rs:15–16` 声称只移动自建窗口，但 `Engine::new(WinPlatform::new(), …)` 未限制目标集合，`175–178` 明确其他应用也进入迁移。当前默认还使用 EngineConfig 的库默认 Grid。这不能证明用户默认模式；也不适合直接在工作桌面循环运行。

修改该测试工具：显式限定本次子进程和所持有窗口集合，真实 backend 枚举/读取/写入全程校验范围；临时 journal 独立；退出/错误恢复只处理本次对象。用产品设置转换得到默认算法；Grid 作为另一个明确案例。确认目标集合外的窗口零写入。真实应用兼容验证使用独立测试登录会话/桌面，打开可丢弃内容，不关闭用户工作窗口来制造全绿结果。

### 4.2 最小必跑场景

1. **真实默认闭环**：目标屏有普通窗，来源屏有不同类型窗口；从 UI/热键整理，核对原目标窗不动、尺寸/模式/焦点与逐窗结果，再恢复核对原位。至少包含 01 末尾的真实应用集和一个明确受限项。
2. **恢复义务可见**：故意保留一个确实无法恢复的测试窗口；进入预览、切页、隐藏/显示、暂停/继续，确认恢复入口和计数；不能以空事务代替。
3. **原位连续**：P→Q→拔原屏→安全救援→换目标→接屏→恢复；再加新窗口 N、主动移动一个旧窗口。原基准保留、外部变更得到保护。
4. **故障恢复**：在 OS 已提交而 Observed 未落盘、部分 Resolved 后、Closed flush 前强杀测试进程；重启并查看/处理记录。包含一个未知身份，不能自动认领同名新窗口。
5. **调度交错**：受支持来源连接、断开第 5 秒重连、暂停、取消、切换目标、维护期间热键排队；核对平台写入与报告都符合代次。真实工具验证与可控轨迹测试分开记录。
6. **平台与发行**：按 05 的 native mac/权限矩阵、Windows 安装自启、坏签名/中断/升级重启验收；Linux 验证明确 unsupported，不测试假显示器成功。
7. **实际 UI**：默认客户区和最小尺寸、100/125/150% DPI、中英文、浅深色、键盘；状态/结果不截断，托盘图标原色一致，托盘菜单也实际点击。

UI 快照可以辅助查裁切/对比度，不能替代窗口坐标、焦点、journal 和进程状态；纯单测不能替代这些桌面场景。非本平台运行、签名或真实远控证据缺失时，保持对应平台/工具为未验证。

### 4.3 现有命令入口

依修改范围先跑相关包/具体回归；合并完成后跑一次适用平台的集成检查，不在每个子任务反复全仓检查。

仓库根目录：

```sh
cargo test -p unfy-domain -p unfy-layout -p unfy-journal -p unfy-engine -p unfy-settings -p unfy-detect
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
```

第一条是相关核心包入口；最终完整 workspace 通过后无需为了计数再重跑第一条。修复目标条件依赖前，跨平台 workspace 失败要按真实原因处理，不能永久缩成只检查一个库。

在 `apps/desktop` 目录运行 `npm run build`，当前脚本已经包含 `tsc --noEmit`、`bun test` 和 Vite build；无需紧接着再跑同一套前端测试。真实窗口用 `npm run tauri dev` 启动；打包验收使用实际安装程序。`cargo check -p unfy-platform-mac --target aarch64-apple-darwin` 只作交叉类型检查，不代替 Mac 上 desktop/settings/tests 和运行验收。

现有 Windows `probe` 无参数是只读枚举入口；`e2e` 在完成上述隔离后才用于自动桌面烟测。修改后运行 `cargo run -p unfy-platform-win --bin e2e`，记录实际输出、测试集合和所用布局。当前 CI 禁用的 `e2e-windows` 应只在有两屏、独立会话的 runner 启用；hosted runner 没有桌面条件时明确跳过，不伪造通过。

## 5. 结果记录与发布门禁

每条证据记录：构建/源码版本、平台与 OS build、应用/远控版本、显示器拓扑/DPI、起始设置、触发入口、预期、实际矩形/模式/结果/未解决数量、日志或截图位置、结论。截图不包含用户敏感内容；统计明示分母，不把权限不足或未知从发现数中抹掉。

性能记录区分首次提交与最终稳定、单窗与整批、冷启动与后台常驻。当前内部观察预算见 01；先解决有界等待与死锁，再在真实应用负载测时。旧文档 100 个同类测试窗的耗时不能沿用为修改后跨应用性能证明。

发布必须同时满足：

- 目标平台全部适用的 W/R/D/UX/P 验收通过，所有 P0 和核心 P1 关闭；被平台明确禁止的能力按真实状态展示。
- 最后一次真实整理/恢复后，报告与 OS 几何一致；确实未解决的窗口仍有 journal 和可操作入口；没有通过清理日志达成“零待处理”。
- 更新/退出不越过维护屏障；旧设置/旧 journal 可解释；签名包、清单和实际新进程相互对应。
- 删除功能的运行入口和死代码已移除，设置迁移仍可读取旧值；没有临时屏蔽错误、硬编码兼容白名单、假日志、Fake 生产回退。
- 修改 README 的当前状态与支持表，更新 `docs/verification.md` 的实际新证据以及受影响的发布说明；旧历史记录保留并注明验证范围。不得继续用“v1 功能完整”代替本轮门禁。

Windows 与 macOS 可以分平台完成验证，但未通过的平台不能挂在同一个“多平台已完成”声明下。UU 入站接口、Mac 原生机器、正式签名身份/更新源属于明确的外部证据条件；其缺失不阻止修完手动闭环、失败处理和本地验收，也不能用猜测填补。

## 6. 给后续实现者的交接指令

先读本目录 README 与 I01 对应的 02/04，再读相关现有源码。按包推进；每次提交只覆盖一个可验证行为集合。保留当前技术栈、原始图标及中性界面。所有当前错误以用户观察和 audit 为已知问题，不重新搬动用户桌面来争论是否存在。

交付时说明改了什么、解决了哪个 W/R/D/UX/P 场景、实际运行结果和仍未验证的平台。若遇到真实外部接口不成立，记录证据并保持该自动能力不可用；不得补上进程/端口猜测、吞错误或写“以后实现”来声称功能完成。
