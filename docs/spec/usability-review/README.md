# Unfy 可用性审查与修订规格

基线：2026-10-25 的当前代码与正在运行的 Windows 应用。交付类型：源码审查、真实 UI 检查、分项实施规格；**应用缺陷尚未在本轮修复**。

结论：当前主要问题是默认整理语义、窗口提交/恢复正确性和各入口状态不一致。继续增加布局、自动开关或美化首页，不能解决这些问题。本轮沿用 Rust/Tauri/React 结构，先修窗口与恢复闭环，再精简交互。

## 修订后的核心契约

1. **默认移入，不压缩整个桌面。** 只移动异屏/越界的合格窗口，保留可用逻辑尺寸与最大化状态；目标屏已有可操作窗口不动。叠放允许，网格是显式高级选项。
2. **先有可恢复记录，再移动。** 没有持久前像与本次 intent 的窗口零写入。准备失败、权限不足、未知身份各自报告；不能靠「全部排除」掩盖兼容性问题。
3. **恢复责任独立于 UI 状态。** 预览不改状态；有记录始终有恢复入口；原位贯穿再次整理、换目标、救援和重启。窗口安全可见但原屏缺失时保留原位记录。
4. **自动动作需要可靠连接证据。** 软件运行、虚拟屏存在、端口已连接不授权整理；查询失败不制造断开。UU 没有已验证入站接口时保留完整手动能力，不伪造自动支持。
5. **所有入口同义。** 窗口、托盘、热键、自动与退出/更新共用动作准入、事务和报告。取消倒计时只取消计时；保留当前位置必须明确确认放弃恢复记录。
6. **图标不变色。** 使用现有原始托盘资源，不按状态/主题重染色；状态通过文本和菜单表达。保留现有中性界面和品牌，不另建视觉系统。
7. **支持能力由实测决定。** Windows 核心先关闭缺陷；mac 完成独立原生门禁后发布；Linux 沿既有决策后移，生产代码不能返回假显示器。

## 保留、删除、合并与延后

| 处理 | 功能 | 原因/落点 |
|---|---|---|
| 保留并修复 | 手动整理/恢复、目标确认、排除、救援、崩溃记录、热键/托盘、自启、签名更新 | 核心闭环；01–05 |
| 保留为高级选项 | 现有网格 | 明确的用户选择，不影响默认移入 |
| 删除 | 主次布局及参数 | 重复布局语义、维护成本高；旧设置迁移为默认，不搬当前窗口 |
| 删除 | 独立手动远程标记、四级灵敏度授权 | 手动操作不需要伪造检测状态；弱证据不授权自动动作 |
| 删除 | 无实现的统计开关、失败卡片「全部排除」 | 前者无效果；后者误导用户用排除替代修复 |
| 删除重复入口 | 主页面/显示器页的循环下一屏按钮 | 与目标卡片/托盘子菜单不同义；统一显式目标选择 |
| 合并 | monitor/tray/commands 的执行、暂停、延期恢复和失败报告 | 单一动作协调，保留真实结果 |
| 收起 | 预览、历史、诊断、网格参数 | 主界面优先目标、状态、下一步；不删除必要能力 |
| 延后，保留明确门禁 | 未证实的工具自动适配、Linux X11、截图等缺失平台能力 | 缺接口或真实后端时诚实降级；不以假数据完成 |
| 不引入本轮 | 虚拟显示器驱动、特权 helper、规则 DSL/云规则包、账户付费、遥测系统、布局模板 | 既有阶段取舍；不解决当前默认整理和恢复问题 |

删除现有功能必须同时迁移旧 settings；不能因 `deny_unknown_fields` 把正常旧配置判损坏。当前已确认的 Windows/macOS 与冲突感知恢复目标保持；Linux、商业化的长期目标不因本轮审查消失。

## 已取得与尚缺的证据

本轮已做：当前实现的分项源码审查；实际 Windows 概览、显示器、排除、设置页面及滚动检查；现存只读 probe 的显示器/窗口枚举。现场观察到「就绪、快照 6、还有 3 个窗口未恢复」并存，源码中的预览状态重置与之吻合。默认算法对整个虚拟桌面的压缩、重置默认与 live engine 不一致、准备失败仍可能提交、日志错误处理等均有代码定位。

本轮没有再次整理/恢复用户桌面，没有执行全套测试、Mac/Linux 原生验证或真实签名升级。现存 probe 与正在运行的应用未在本轮重构建。用户报告的默认效果和窗口失败作为问题事实；这些审查定位不能代替后续跨应用逐项验证。原截图含桌面内容，不写入仓库。

缺失的外部证据列在 03/05/06：UU 可靠入站生命周期接口、macOS 原生多屏/权限测试、正式签名与更新源。它们限制对应能力的发行声明，不妨碍实施和验证其余已知修复。
