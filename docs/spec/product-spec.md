# Conflux 产品规格（PRD）

> 状态：实现前基线；日期：2026-10-21；产品名暂定。本文定义用户行为、范围与验收；接口、类型、算法见 [技术设计](technical-design.md)，技术取舍见 [ADR](decisions.md)，版本门槛、商业条款与发布范围见 [路线图](roadmap.md)。

## 1. 产品目标与事实约束

Conflux 安装在被远程访问的主机上，在经过验证的入站远程连接出现时，将当前用户会话中可安全控制的窗口收拢到用户指定的显示器；连接结束后恢复原布局。对具有独立显示拓扑的远程会话，只救援本会话的越界窗口。它不传输屏幕，也不建立远程连接。

### 1.1 用户问题与结果

| 问题 | 用户可观察的结果 | 产品不作的推断 |
|---|---|---|
| 主机有多屏，远程端仅显示其中一屏 | 符合策略的窗口出现在用户已确认可见的目标屏，排列后可继续工作 | 不能因为远程工具在运行就断言有人正在连接 |
| 多屏上保存的位置落到单屏会话之外 | 当前会话中的越界窗口回到可见工作区 | 不从 console、其他用户或其他远程会话拉取窗口 |
| 远程结束后需要回到本地多屏工作 | 未被用户主动改动且仍可识别的窗口恢复；其他窗口解释保留/跳过原因 | 不根据相同标题将新启动窗口冒认为旧窗口 |
| 自动化误判可能打断本地工作 | 首次配置可验证；低置信度只提示；随时暂停、恢复和救援 | 不将启发式目标屏描述为“已识别到远程捕获屏” |

### 1.2 本文中的事实与设计值

- **已知约束**：客户确定的技术栈、目标平台及主场景；API 的存在不等于目标环境中的操作成功。平台能力仍需真实设备验证。
- **产品设计值**：以下阈值、时长、默认开关、SLO 和套餐是拟实现的行为合同，不是第三方 API 的参数或厂商保证；M0 后依据证据调整时必须同步本文、技术设计和验收用例。
- **`[待验证]`**：第三方能力、版本、路径、参数、权限交互尚未得到可靠证据。必须记录验证环境、方法、结果、负责人和日期，未关闭不得转为“支持”宣传。
- 本文不规定第三方日志路径、注册表路径或静默安装参数。相关候选仅可在技术设计/路线图中以 `[待验证]` 标记并附验证方法，不得从软件名称推导路径。

### 1.3 范围与发布约束

| 范围 | 合同 |

## 2. 人物画像与 JTBD

| 人物 | 环境与约束 | JTBD | 成功标准 |
|---|---|---|---|
| A：多屏知识工作者（首要） | 办公室三屏主机；出差时用单屏笔记本远程；不理解 DPI、会话或驱动 | 当我远程回主机时，让需要的窗口直接可用；断开后回到原来的工作习惯 | 首次设置后无需切换远程显示器；误判不搬窗；返回办公室无需手工重排 |
| B：开发者/设计师（次要） | 20–100 个窗口、混合 DPI、工具常开；会调整布局；偶尔有管理员窗口或全屏应用 | 将当前工作的应用收拢，同时尊重我在远程期间主动做的调整 | 焦点与文本输入不中断；知道哪些窗口未能控制；手工改动被保留 |
| C：远程桌面使用者（次要） | Windows RDP、xrdp 或具有独立桌面的 VNC；应用记住了旧坐标 | 当窗口打开在看不见的位置时，把它找回来 | 只影响当前会话；可见窗口不被重新排布；无需注销或重启应用 |
| D：企业 IT 管理员（M4） | 无本地管理员权限、受管设备、更新审批、离线网络和审计要求 | 在合规范围内降低远程支持工单，并控制权限、配置和更新 | 用户版可降级运行；策略可审计、可撤销；没有隐藏提权或屏幕数据采集 |

排除的首要用户需求：远程游戏低延迟串流、屏幕录制、云桌面编排、跨用户协作桌面、由远程客户端强制控制主机显示模式。

## 3. 核心概念与安全合同

| 概念 | 定义与行为 |
|---|---|
| mirror | 远程工具捕获当前物理会话的一块或多块屏幕。检测连接和确定捕获源是两件事；前者成功不意味着后者已知 |
| session | 当前进程所在的远程用户会话有自己的显示拓扑。仅检查本会话窗口是否可见，不处理其他会话的布局 |
| 目标屏 | 用户配置并确认远程端可以看到的显示器；默认建议主显示器，不能标成自动发现的捕获源 |
| 基线快照 | 第一次真实修改窗口之前写盘的原始布局；同一远程周期内重连、换目标屏和重新排布不覆盖它 |
| 窗口身份连续性 | 引擎连续观察窗口创建/销毁时可维护运行期 generation；崩溃会中断这条证据。进程、句柄、类名等复合指纹仅用于候选核验，不保证跨崩溃唯一；不能证明同一窗口时，原位置恢复须用户预览确认 |
| 远程周期 | 同一用户会话内，从首次迁移到所有来源结束且完成恢复的事务。多个连接来源由来源集合管理，不按每条 TCP 连接各建一次事务 |
| 可迁移窗口 | 当前会话和允许桌面内、有效且可见的普通应用窗口；满足平台权限、排除规则和状态约束；不等于系统全部窗口 |
| 可见性优先 | 原屏不存在、旧矩形越界等情况下，先在现有工作区保持可用，再报告无法精确恢复；不为复刻旧坐标将窗口放回不可见区域 |
| 用户改动 | 迁移后，非 Conflux 自己提交且超出容差的窗口位置/尺寸变化。无法区分应用自我纠正与用户拖动时，保守视为外部改动 |
| 干跑 | 执行检测、计算候选、输出原因和计划，不移动窗口、不改变显示拓扑；可安全用于规则验证 |

### 3.1 必须保持的不变量

1. 在任何窗口发生修改前，能够持久化其身份和原始位置；快照写入失败时禁止开始新迁移。
2. 同一事务只能有一个写入者；恢复优先于新的迁移、规则更新、更新重启和用户退出。
3. 任何可控制窗口的恢复目标必须与当前真实工作区相交且保留可操作区域；不能把“成功提交 API”当作“窗口已可见”。
4. 系统拒绝访问、窗口已消失、身份不确定、断电或被强杀时无法保证即时恢复；不得伪报成功。保留未完成记录，下一次启动重新核验并提供恢复/救援。
5. Conflux 不跨用户、登录会话、锁屏安全桌面操作；锁定或用户切换时暂停新动作，恢复当前交互会话后再核验。
6. 用户可随时执行“恢复本次布局”“救援越界窗口”“暂停自动整理”；付费到期、网络离线、更新失败和规则故障不得封锁这些入口。
7. 任何新增检测规则都不能扩大窗口操作权限；任何签名规则包都不能运行任意脚本或包含任意命令执行逻辑。

“窗口不得永久留在不可见区域”是可恢复性要求：所有受控修改均有日志、可用恢复入口和可见回退目标。它不是对 OS、应用、磁盘损坏、突然断电或用户卸载后仍能运行代码的保证。

## 4. 端到端用户旅程

| 阶段 | 用户行为与界面 | 系统行为 | 失败/退出路径 |
|---|---|---|---|
| 1. 获取与安装 | 从官网选择当前平台；看到签名发行者、版本和支持范围 | 使用受支持的安装包；首次启动不申请管理员权限、不加载驱动 | 安装失败给出发行版本、架构和错误码；不提示关闭 OS 安全保护 |
| 2. 模式说明 | 向导用“把多屏窗口收拢到一块屏”“找回当前会话的越界窗口”区分需求 | 读取当前会话和显示拓扑；不采集屏幕画面 | 无法判定时默认手动模式，可跳过工具选择 |
| 3. 权限检查 | macOS 看到系统控制窗口所需授权；Windows/Linux 查看可控制范围 | 仅请求当前功能必要权限；未授权时禁用动作并保留预览 | 拒绝权限不循环弹窗；“稍后设置”进入 Degraded，仍能查看设置/诊断 |
| 4. 确认目标屏 | 看到编号、分辨率、主屏标识；点击“识别屏幕”；远程端确认看到标记 | 默认建议主屏，以稳定身份保存；标记为临时文字/色块，非截图 | 无第二块屏仍可完成会话救援设置；无法确认远程捕获源时保留干跑 |
| 5. 试运行与启用 | 点击“预览将整理的窗口”，再试一次迁移和恢复；明确开启自动整理 | 先建立事务再迁移；展示可移动/跳过数量；自动化默认在完成确认后启用 | 跳过试运行则保存配置但不自动搬窗；试运行失败回到手动/干跑 |
| 6. 日常零打扰 | 托盘显示“已就绪”；无需打开主窗口 | 监听经过验证的入站证据；弱信号、客户端主动连出、后台服务存在都不触发迁移 | 规则未知或权限变更时仅发一次合并通知；不弹设置窗口抢焦点 |
| 7. 远程连接 | 用户在远程端看到原工作窗口 | 双独立信号达阈值并去抖后迁移；按布局分配槽位，保持焦点语义 | 无法证实连接方向/捕获屏时仅提示手动整理；部分失败展示数量和原因 |
| 8. 远程中 | 托盘/热键换目标、重排、排除应用、暂停；可打开新窗口 | 换目标复用原始基线；新增窗口默认保持应用选择，仅救援越界；用户显式重新整理时为新纳入窗口追加记录；不持续抢回用户拖动的窗口 | 原目标消失即停止旧计划、重新核验拓扑；优先救援可见性并提示用户重新确认远程可见屏 |
| 9. 连接断开 | 托盘显示“连接已结束，15 秒后恢复”；可“立即恢复”或“暂不恢复” | 等全部来源结束后开始倒计时；重连取消倒计时并合并周期 | 信号来源中断不等于断线，先进入不确定状态；不因检测器崩溃立即反复搬窗 |
| 10. 恢复 | 用户回到原多屏工作；必要时看到摘要 | 未外部修改的存活窗口恢复原状态；用户改动默认保留；丢屏时回退可见区域 | 显示“已恢复 17、保留改动 2、已关闭 1、需处理 1”；不只给一个成功率 |
| 11. 崩溃后再启动 | 看到“上次整理未完成”；可查看候选并确认恢复 | 核验 journal、当前登录会话、窗口身份和显示器；无法重新证明身份时不自动应用旧坐标，提供候选预览 | journal 损坏、身份不明则禁止基于旧快照移窗；可对当前会话执行通用越界救援与导出脱敏诊断，不声称这是精确恢复 |
| 12. 更新、退出与卸载 | 空闲时自动更新；点击退出/卸载得到恢复进度 | 先停止新任务，再完成恢复和落盘，最后退出/安装/清理；无法恢复则阻止应用内普通流程并提供修复入口 | OS 强杀/断电不受此拦截保证；下次启动接管恢复。手动删除应用的风险在卸载说明中明确 |

首次向导同时呈现：开机自启默认关闭；自动下载安全更新默认开启；匿名遥测默认关闭；应用主题跟随系统、语言跟随系统并可切换。用户选择分别持久化，不与开通 Pro 绑定。

### 5.4 每个 P0 的 Given/When/Then 验收

以下用例中的窗口均指测试宿主生成的已知可控窗口，另有明确反例时除外。每次执行保存 OS/架构、显示拓扑、权限、客户端版本、规则版本和结果。标为“不得”的副作用为零容忍，不用平均成功率抵消。

| 用例 | Given | When | Then |
|---|---|---|---|
| P0-01-A | 全新用户配置、三屏、未完成向导 | 首次启动 | 不移动任何窗口；展示平台/会话/权限状态；自动整理、遥测和开机自启尚未获得用户开启授权 |
| P0-01-B | 支持组合、权限齐备、用户确认目标屏并成功试运行恢复 | 点击“启用自动整理” | 进入 Armed，保留选择；再次启动不重复向导；可从设置重新运行 |
| P0-01-C | 平台/架构匹配且签名有效的发布包，以及签名失效或架构不匹配的反例 | 执行该包形态的安装验证 | 正例按声明权限安装；反例被 OS/安装器或产品安装检查明确拒绝并给出解决路径；不得引导关闭系统安全保护，不能把需要权限的安装误称为零权限安装 |

## 6. 关键交互与行为规则

### 6.1 触发、连接确认与目标屏

| 项目 | v1 默认行为 |
|---|---|
| 自动整理开关 | 用户完成试运行和启用确认后为开；开启动作不得自动移窗，仍等后续有效证据 |
| mirror 检测门槛 | 已验证规则至少两个独立信号、至少一项证明本会话的入站活动；设计阈值 score ≥ 0.90、稳定 2 秒。分数是启发式而非统计概率；弱证据不能通过叠加权重突破入站硬门槛 |
| session 救援门槛 | 可由经过平台验证的权威 OS 本会话信号确认，不机械要求两条弱证据；同时检查当前会话活动性、权限与拓扑。此例外只允许本会话越界救援，不能升级为 mirror 迁移或跨会话操作 |
| 冷却 | 一次自动周期/主动撤销后 30 秒抑制同源重复触发；重连合并和紧急可见性救援不受冷却阻断。手动请求允许执行并记录 |
| 未知/实验工具 | 默认干跑；用户可手动整理。未经工具/版本/OS 测试证据批准，不能通过“总是触发”开关变成静默自动搬窗 |
| 目标屏默认 | 主显示器为候选，向导让用户在远程端确认标记可见；手动指定优先于规则启发式，规则启发式优先于默认主屏 |
| 首次/拓扑变化 | 捕获屏未知须明确写“请确认远程端能看到此屏”。已经验证的显示器身份仍存在时可沿用；身份变化、歧义或原屏消失时暂停自动迁移 |
| 目标循环 | 在当前活动且可用的所有显示器间循环，包含用户已有的虚拟显示器；瞬时显示目标名称/编号，不修改原基线。v1 不安装显示驱动、不提供“创建虚拟屏”选项；已有虚拟屏仍需用户确认远程端可见 |
| 多屏捕获 | 用户选择“远程端可见全部屏幕”时默认不收拢，保留越界救援；允许用户手动选择需要收拢的目标 |
| 工具品牌 | TeamViewer、AnyDesk、RustDesk、Parsec、Sunshine、NoMachine、VNC、ToDesk、向日葵、RDP、macOS Screen Sharing 均是兼容性验证对象；品牌出现在列表中不等于其所有模式已支持 |

各工具的信号、可靠性评级、未验证路径与验证计划见技术设计。UI 必须分别展示“已确认连接”“候选信号”“未适配”，不能把一个统一绿色“兼容”标识套用到全部工具。

### 6.2 布局与窗口状态

| 条件 | 规则 |
|---|---|
| 1 个窗口 | 保留用户期望的正常尺寸，在目标工作区内居中/夹紧；原本最大化则恢复最大化 |
| 2–4 个窗口 | 默认主次分区，焦点窗口优先；用户可选均匀网格 |
| 5 个及以上窗口 | 按有效工作区与最小尺寸选择网格；装不下时以焦点窗口为主，其余可访问级联，提供窗口列表；不保证所有窗口同时完整可见 |
| 应用最小尺寸大于工作区 | 保留应用约束、保证受支持的标题栏/拖动控制区域可达并提示空间不足；无法保证可操作区域时报告受限，提供应用/OS 手动调整指引，不谎报完整可见 |
| 保留相对顺序 | 在可行区域内保留屏幕阅读顺序、层级与相对尺度；不能保证精确复制多屏比例到单屏 |
| 最小化 | 默认保持最小化，不抢前台；记录可恢复的正常矩形；展开后发现越界再救援。平台无法安全改写正常矩形时跳过并说明 |
| 最大化 | 保存正常矩形和最大化状态，必要时短暂还原后迁移再重建；恢复时重新核验当前工作区 |
| 全屏/无边框全屏/DRM | 默认排除，不擅自退出全屏、切换 Space 或改变显示模式；用户可以退出全屏后重试 |
| owner/模态对话框 | 与所属主窗口作为关系组评估，不能把对话框与主窗口分到不同屏；关系或控制能力不明时跳过整组/提示，禁止单独搬走 |
| 置顶与焦点 | 不新增置顶、不把后台窗口激活为前台；尽可能保留原有层级。无法完整恢复 z-order 时报告有限恢复，不循环抢回焦点 |
| 应用自我纠正 | 有限次数复核，持续拒绝或回弹则停止该窗口操作并建议排除；不与应用持续争夺位置 |
| 虚拟桌面/Spaces | 默认仅处理当前可访问桌面；其他桌面窗口不保证枚举或迁移；禁止未经授权切换桌面 |
| UWP/特殊框架 | 通过宿主/实际应用对应关系识别后才加入；身份不确定跳过，不将所有框架宿主混为一个应用 |

### 6.3 恢复与异常策略

| 场景 | 默认策略 | 用户配置 |
|---|---|---|
| 正常断开 | 最后一个来源确认结束后延迟 15 秒，恢复未被外部改动的窗口 | 自动恢复延迟可设 15–120 秒，默认 15 秒；“立即恢复”为用户显式操作，不受该最短延迟限制；可“本次暂不恢复”。数值为产品设计范围 |
| 检测状态不明 | Active 因来源状态 unknown 进入 Degraded 时，保持现有布局、原基线和来源集合，合并一次通知并停止新增自动操作；重新证实同一远程仍活动时回到 Active，不自动恢复 | 仅最后一个来源明确断开并经过配置延迟、用户显式恢复，或其他恢复屏障成立时进入 Restoring；未知状态本身不构成断线 |
| 用户移动/缩放过 | 保留改动，仅修正越界；摘要说明保留多少 | 可选择“始终恢复连接前布局”，需明确文案，不影响可见性优先 |
| 原屏缺失 | 使用当前有效目标屏/主屏上的可见回退；标为回退恢复 | 用户可重新选择仍连接的显示器；禁止选择不存在的屏 |
| 显示器身份有歧义 | 不按屏幕索引冒认；进入降级并要求用户选择 | 人工重新绑定，后续周期使用新绑定 |
| 窗口关闭、进程重启或系统重启 | 原身份失效则标为关闭/无法确认；崩溃后复合指纹只能形成候选，不能默认证明窗口连续存活 | 候选原位置恢复需用户预览确认；可对当前会话执行通用越界救援；不“恢复”应用内容或重开应用 |
| 用户放弃原位恢复 | 提供候选详情、当前可见性检查及不可控项说明，用户可明确选择保留当前布局并解决相关记录 | 不做单击“全部成功”；记录用户确认的原因而非精确恢复；仍无法确认可见且未处理项保留 pending，不借此清空 journal |
| 退出、更新、卸载 | 优先完成恢复屏障；无法完成则展示未恢复项并阻止产品提供的普通退出/安装流程 | 重试、重新授权、打开手动救援指引；OS 强制终止仍只能依靠下次启动恢复 |
| 注销/OS 关机 | 收到通知时尽力恢复并刷新 journal；不能阻止/延长到保证所有应用响应 | 无永久阻塞系统关机；下一次启动检查遗留记录 |
| 权限撤销 | 停止操作并保留恢复记录；无法控制的窗口明确标“等待授权” | 恢复权限后优先完成待恢复任务；用户从系统直接撤权时不虚构已恢复 |
| 全部窗口不可控 | 不开始空事务或反复尝试；显示原因分类 | 手动指引或排除规则；不建议默认以管理员运行整套应用 |

### 7.2 操作反馈和设置一致性

- 设置采用立即保存的轻量项目和明确的“应用”行为区分：主题、语言可立即生效；更换目标或布局可能移动窗口，Active 期间必须选择“应用于本次”或“仅用于下次连接”。
- “暂停自动整理”默认先恢复当前事务再进入 Idle；另提供明确标注的“保持当前布局并暂停检测”。后者保持 Active 并设置 paused 标志，保留待恢复记录，托盘始终显示“布局仍在使用 · 检测已暂停”和“恢复本次布局”；Idle 不得隐藏未解决事务。
- 点击“恢复本次布局”后，不因仍存在的相同连接证据立即再次迁移；将该来源标为本周期已人工结束，直到新连接边缘或用户重新开始。
- 高级/Pro 页面不得成为恢复入口的唯一位置。主页面、托盘、错误页面均可直接到达恢复/救援。
- 中文长度、英文长度、125%–200% UI 缩放、键盘焦点、屏幕阅读器名称和不依赖颜色的状态文本属于界面验收范围；动画遵循系统减少动态效果设置。

## 8. 托盘状态机

托盘 UI 与核心八状态一一映射，颜色仅作辅助。`Degraded` 和 `Error` 同时展示是否仍有活动事务，避免用户把“已降级”理解成“已恢复”。具体转换和并发规则以技术设计为准。

| 核心状态 | 中文标签/图形语义 | 进入条件 | 主菜单动作 | 通知与退出条件 |
|---|---|---|---|---|
| Idle | “自动整理已暂停”，静止空心图标 | 初次未启用、主动暂停或检测关闭，且没有未解决事务 | 整理到目标屏、救援越界、启用自动整理、设置、退出 | 不主动通知；完成启用/权限检查进入 Armed；发现待恢复记录转 Restoring/Degraded/Error |
| Armed | “已就绪”，常规图标 | 自动化开启、权限和目标配置有效、无待恢复事务 | 手动整理、救援、暂停、目标屏、设置、退出 | 不弹通知；出现候选证据进 Detecting |
| Detecting | “正在确认远程连接”，缓慢状态点 | 有候选证据但尚未通过全部门槛 | 查看依据、手动整理、暂停、设置 | 默认无通知；证据消失回 Armed；确认后进入 Migrating，未知/不支持能力转 Degraded |
| Migrating | “正在整理 3/12 个窗口”，有限进度 | 基线持久化成功后执行有界计划 | 停止并恢复、查看详情；目标/布局更改排队 | 完成进 Active；部分失败可进 Degraded；无法安全继续进 Error 并启动可执行恢复 |
| Active | “远程布局已启用 · 屏幕 A”，填充图标；paused 时“布局仍在使用 · 检测已暂停” | 迁移完成或用户保持布局；显示来源数与计数；paused 不清除事务 | 恢复本次布局、换目标、重新排布、保持布局并暂停/恢复检测、设置 | 进入时最多一次轻通知；全部来源结束后本状态显示 15 秒恢复倒计时，重连取消；明确暂停检测并保留布局时不假设已断开 |
| Restoring | “正在恢复 3/12 个窗口”，反向进度 | 断线倒计时结束、用户恢复、退出/更新/卸载屏障、崩溃恢复 | 查看进度/失败原因；禁止并发新迁移与清理 journal | 成功回 Armed/Idle 并继续已排队退出/更新；部分未完成转 Degraded/Error |
| Degraded | “功能受限：需要授权/确认目标/手动模式”，叹号 | 平台不支持、部分窗口拒绝、检测失联、权限缺失、拓扑歧义等可解释限制；保留具体降级原因及原状态 | 修复原因、可执行的恢复/救援、手动整理（能力允许时）、诊断、设置 | 每个原因周期合并一次提示；检测 unknown 修复且证实同一远程仍活动时回 Active；仅已满足明确断线延迟、用户恢复、生命周期屏障或启动遗留 journal 等恢复条件时转 Restoring，不因“修复完成”一律恢复窗口 |
| Error | “操作未完成，窗口恢复需要处理”，错误标记 | journal 损坏、持久化失败、不可恢复状态机错误、恢复重试耗尽 | 重试恢复、可执行的救援、诊断、查看指引；普通退出受恢复屏障约束 | 强提示一次，不反复弹窗；未安全关闭事务不得自动回 Armed；OS 强制终止仅留待下次启动处理 |

“退出”不是第九个稳定状态。用户点击后进入 Restoring，事务安全关闭且 journal 刷新后才结束进程。无事务时可直接退出。Wayland 不伪装为 Active 迁移成功，显示“当前桌面仅支持通知与操作指引”。

通知要求：默认不抢焦点、不自动打开设置窗口、不播放声音。仅首次权限失败、不可继续的恢复错误、用户主动操作失败和目标丢失产生系统通知；重复原因合并。用户关闭通知不关闭托盘状态或恢复入口。

## 10. 质量、指标与观测合同

以下为 M3 候选门槛，数值属于产品设计值；M0 校准测试硬件和测量口径，不能用无证据数字对外作实际性能承诺。最终发布阈值必须在路线图退出门槛中一致列出。

| 指标 | 口径/分母 | M3 门槛或目标 | 失败处置 |
|---|---|---|---|
| 迁移成功率 | 已纳入计划且声明可控的窗口中，提交后读回满足目标布局/可见性要求的比例；筛选跳过独立报告 | ≥99%（受控兼容性集）；零跨会话/无证据自动迁移 | 单一平台/工具失败不能被平均掩盖；降级并阻断相应支持声明 |
| 恢复成功率 | 合格窗口达到其预先声明的安全终态：原位恢复、按用户改动保留、原屏缺失时安全替代；仍存活窗口的运行时拒绝和超时计失败，关闭项单列 | ≥99.9%；对已可控制窗口可见性恢复 100% | 任一不可见回归未关闭，阻断发布；不能把“待处理”当成功 |
| 原位精确恢复/救援 | 另列满足原位恢复条件的窗口中，位置/尺寸/可支持状态复原比例；救援成功按当前有效工作区的可操作性统计 | 原始分子/分母和例外分别报告；不得用安全替代冒充原位恢复 | 用户保留、关闭、身份不确定、丢屏回退分别列项；不得混用分母 |
| 错误自动动作比例 | 全部自动动作决策中，ground truth 为无入站远程的误触发比例，即错误自动动作/全部自动动作 | ≤0.1%，与下行负例误判率同时达标；报告样本量与区间 | 不能用检测准确率或大量真负例替代此产品体验口径 |
| 检测判决误报率 | ground truth 为无入站远程的已标注判决中，被判为可自动动作的比例，即 FP/(FP+TN)；周期和采样规则需预先固定 | ≤0.1%；M2 至少 5,000 个已标注检测判决；同时报告分母、平台/工具分组和区间 | 不把高频重复采样的 TN 用于稀释误报；违规规则降为干跑 |
| 误搬频率 | 已知无入站远程的本地使用主机小时中，未经手动授权而实际移动窗口的次数 | 至少 10,000 个无远程主机小时，误搬 ≤1 次；同时报告样本量与区间 | 禁用涉事规则的自动模式，保留手动和恢复；“零观测”不宣称总体绝不误报 |
| 自动检测覆盖 | 已验证工具/版本/mode 的实际入站会话中，完成确认的比例；不将未知工具计入高覆盖宣传 | 单组合报告；M0 定基线后由 QA/产品签署门槛 | 覆盖不足降为手动，不为提高覆盖下调安全硬门槛 |
| 迁移 p95 | 从触发已确认到整个计划100窗首轮请求全部提交，包含枚举、布局、journal 持久化和原生调用；排除此前 2 秒检测去抖 | 100 窗口基准 p95 <300 ms；同一起点到整批可见稳定 p95 ≤1 秒；超时不得从样本剔除 | 分批调度不改变整批终点；不能把未完成的异步提交算完整稳定，不能省略写盘来满足指标 |
| 空闲资源 | 窗口关闭但托盘/检测运行、无活动迁移；统一 CPU 口径、稳定采样区间；包含 UI 所需子进程 | 空闲平均 CPU <1%；RSS <120 MB | 记录 OS/架构/运行时；达不到则优化/披露，禁止只测 Rust core 掩盖总占用 |
| 稳定性 | 24 小时常驻、100 次连接循环、注入中断与权限/热插拔变化；崩溃按设备会话统计 | 崩溃自由会话率 ≥99.9%（公测口径）；恢复链专项无未关闭严重缺陷 | 崩溃循环进入禁用自动迁移的安全模式；保留 journal |
| 界面 | zh-CN/en、主题、缩放、键盘和辅助技术检查 | P0 主流程无截断、无不可达按钮、无颜色唯一状态 | 阻断相应版本发布 |

M2 公测至少覆盖 100 台活跃主机、5,000 个已标注检测判决、10,000 次合格窗口迁移和另 10,000 次恢复；M3 继续累计至误搬频率门槛要求的无远程主机小时。样本分布和纳入/排除标准在测试开始前冻结，不能把运行时拒绝、超时、失败导致未提交或事后才判为“不可控”的窗口追溯移出分母；取消、窗口关闭、拓扑失效另列原因但不删除计划样本。检测按独立连接 episode 和预排30分钟负例观察窗去重，unknown不计TN；精确指标来自受控实验或另行同意的公测研究，不能从匿名分桶遥测推算主机数/小时/无崩溃会话。完整统计定义见技术设计§13。

本地日志记录状态转换、原因码、能力限制、事务阶段、窗口计数、分阶段耗时、规则版本和脱敏会话标识；默认不记录窗口完整标题、原始第三方日志、屏幕内容、按键、剪贴板、远端地址和原始显示器序列号。诊断导出必须有内容预览和取消入口。日志与可选匿名遥测的字段白名单、保留期、聚合与删除方式见技术设计；实现前必须与隐私政策一致。

遥测需显式同意，拒绝不影响软件功能；订阅验证和更新检查是各自目的所需的网络活动，需在隐私政策中独立披露，不能伪装成用户已同意行为遥测。未经用户授权不自动发送支持工单或诊断包。

## 12. 非目标与发布前待决事项

### 12.1 非目标

- 不实现远程桌面传输、远程认证、录屏、键鼠注入、内容分析、音视频路由或远程工具的连接功能。
- 不宣称能从所有远程软件查询当前捕获源；不修改第三方配置文件、破解协议或绕过访问控制来获得该能力。
- 不跨用户/登录会话迁移窗口，不绕过 UAC、TCC、锁屏安全桌面或 Wayland compositor 的权限边界。
- 不恢复被关闭应用的内容，不自动重新打开应用，不把系统重启后的同名新窗口认作旧窗口。
- 不保证所有应用、全屏 Space、独占游戏、DRM 窗口或提权窗口都可移动；失败和跳过必须可解释。
- v1 不安装驱动或特权服务，不创建专用虚拟显示器，不禁用副屏，不切换系统显示模式。
- 不承诺非 Windows 平台的强制单屏，不将私有 API、社区内核模块或桌面扩展写成通用平台保证。
- 不做完整窗口管理器、快捷键自动化平台或跨设备布局云同步；不将用户窗口标题/布局上传用于模型训练。
- 不将恢复、救援、安全更新、诊断或删除数据作为付费转化手段，不在远程工作途中用营销弹窗打断用户。
